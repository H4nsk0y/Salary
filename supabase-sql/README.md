# Supabase SQL

Здесь хранятся SQL-скрипты, которые нужно запускать вручную в Supabase SQL Editor.

Правила:
- новые изменения добавлять отдельным файлом с номером и коротким названием;
- SQL по возможности делать idempotent: `if not exists`, `create or replace function`, проверки через `do $$`;
- не использовать `drop` без явной необходимости;
- если скрипт уже запускался, не удалять его из папки: это история изменений БД.
- не сохранять в репозиторий реальные UUID сотрудников, токены, ключи или другие чувствительные данные без явной необходимости.

Пример имени:

```text
001_user_presence.sql
002_owner_reports.sql
003_department_settings.sql
```

Актуальные security-файлы:

- `026_security_hardening.sql` - серверная защита профилей, табелей, уведомлений, push-подписок и аватаров;
- `027_security_audit_report.sql` - безопасный отчёт только на чтение по grants, RLS, функциям и триггерам.
- `028_secure_egais_cron.sql` - защищает плановые уведомления ЕГАИС отдельным секретом cron.
- `029_restrict_security_definer_execute.sql` - убирает неявный анонимный доступ к `security definer` RPC, сохраняя доступ авторизованного приложения.
- `030_egais_department_timesheet_view.sql` - дает сотрудникам ЕГАИС безопасный доступ к общему графику без окладов, фактических выплат и прав редактирования.
- `031_staff_voting.sql` - анонимное недельное и месячное голосование за сотрудников с фиксацией победителей и публикацией комментариев после завершения периода.
- `032_shift_checklists.sql` - личные чек-листы смены, защищенные RPC и трехчасовые push-напоминания через cron.
- `033_project_ideas.sql` - предложения пользователей через сайт и защищенный owner-список идей.
