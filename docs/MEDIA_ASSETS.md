## Подготовка ресурсов

Использован установленный FFmpeg, без новых npm-зависимостей:

```powershell
ffmpeg -i source.png -vf scale=144:216:flags=lanczos -c:v libwebp -quality 86 -frames:v 1 output-144.webp
ffmpeg -i source.mp3 -map 0:a:0 -map_metadata -1 -c:a libmp3lame -b:a 160k -id3v2_version 3 output-160k.mp3
```

Для остальных вариантов картинки меняются размеры на 72:108 и 216:324.
Исходники не следует затирать до проверки результата.

## Повторные загрузки

Service worker v8 использует Cache Storage в первую очередь только
для известных компактных праздничных картинок, двух новых MP3 и
публичных изображений/шрифтов с параметром версии `v`. JS, CSS,
неверсионированные картинки и HTML не переведены на cache-first.
Авторизация, запросы Supabase и финансовые данные не кешируются этой
новой политикой.

Первое воспроизведение MP3 начинается потоком, полная копия сохраняется
параллельно. После полного скачивания следующие страницы используют
её без сети. При перемотке из полной копии формируются ответы 206 с
правильными Content-Range и Content-Length. Ответы 206 с сервера не
сохраняются как полные файлы. Если кеш недоступен или заполнен,
остаётся обычная загрузка из сети. Без установленного service worker
используется стандартный HTTP-кеш браузера.

Крупные MP3 не добавлены в предварительную загрузку или offline shell:
загрузка начинается только при включении музыки. При замене содержимого
cache-first ресурса нужно изменить его URL (имя или `?v=...`) либо
повысить CACHE_VERSION. Новая версия service worker применится после
обычного принятия обновления PWA; принудительной перезагрузки нет.
