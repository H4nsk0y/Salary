# Security audit

Проверка выполнена для статического клиента Alvisa, Supabase RLS/RPC, Storage и Edge Functions.
Этот документ фиксирует защищённые места, порядок применения серверных изменений и оставшиеся риски.

## Что исправлено

- Закрыта подмена `next` и внешние переходы через вход, профиль, уведомления и Service Worker.
- Поля профиля ограничены белым списком в `db.js`; роль и служебные поля защищаются БД.
- Добавлена серверная проверка профиля, табеля, фактических сумм, уведомлений и push-подписок.
- Табель ограничен размером 256 КБ, корректным месяцем, допустимыми кодами и максимумом 24 часа в сутки.
- Загрузка аватаров ограничена папкой пользователя, размером 2 МБ и форматами JPEG/PNG/WebP.
- Плановая Edge Function ЕГАИС требует отдельный секрет, которого нет в клиентском коде.
- Ссылка восстановления пароля owner-функции разрешена только для официальных страниц входа Alvisa.
- Новые денежные PIN хешируются PBKDF2-SHA256; старые PIN продолжают работать.
- Динамические названия отделов и URL уведомлений больше не вставляются как доверенный HTML/URL.
- Добавлены автоматические проверки в `tests/security-regression.test.mjs`.
- Tailwind больше не выполняется через CDN: стили собираются локально и проверяются в CI.
- На HTML-страницах действует базовая CSP с ограниченным списком разрешённых источников.
- Существенные клиентские ошибки отправляются через ограниченный RPC; сетевые сбои, отсутствие VPN и отменённые запросы отбрасываются.

## Что выполнить в Supabase

1. Сделать резервную копию БД.
2. Запустить `supabase-sql/026_security_hardening.sql` в SQL Editor.
3. Запустить `supabase-sql/027_security_audit_report.sql` и проверить, что у `authenticated` нет права обновлять `profiles.role`.
4. Выполнить `supabase-sql/029_restrict_security_definer_execute.sql`, затем повторить отчёт `027`: оба списка функций должны быть пустыми.
5. Создать отдельную случайную строку длиной не менее 32 символов для cron.
6. Сохранить её в Edge secrets как `CRON_SECRET`, а в Vault как `alvisa_egais_cron_secret`.
7. Заново развернуть `send-egais-file-reminders` и выполнить `supabase-sql/028_secure_egais_cron.sql`.
8. Заново развернуть `owner-account-admin`.
9. Выполнить `supabase-sql/035_client_error_logging.sql`, чтобы включить защищённый журнал серьёзных ошибок.

Реальное значение cron-секрета нельзя записывать в Git или отправлять в клиентский JavaScript.

## Проверка ролей после SQL

Проверить минимум тремя учётными записями:

| Сценарий | Обычный сотрудник | Редактор отдела | Owner |
| --- | --- | --- | --- |
| Изменить собственный профиль | Да, кроме роли | Да, кроме роли | Да |
| Самостоятельно назначить себе owner | Нет | Нет | Не применимо |
| Читать чужой профиль | Нет | Только доступный отдел | Да |
| Изменить табель ЕГАИС | Нет | Только свой отдел | Да |
| Вызвать owner RPC/Edge Function | Нет | Нет | Да |
| Загрузить файл в чужую папку аватаров | Нет | Нет | Нет |

## Оставшиеся ограничения

- PIN скрытия денег защищает от случайного просмотра на открытом устройстве, но не заменяет пароль аккаунта.
- Результат мини-игры рассчитывается клиентом, поэтому технически подкованный пользователь может подделать счёт. На персональные и финансовые данные это не влияет.
- Supabase JS, Driver.js и шрифты пока загружаются с разрешённых внешних источников. Для более строгой CSP потребуется локализовать их и вынести оставшиеся inline-скрипты и стили.
- Статический анализ не заменяет проверку фактических grants и RLS в рабочей БД. Для этого нужен результат `027_security_audit_report.sql`.
- Активные нагрузочные и разрушающие тесты на рабочей БД не выполнялись, чтобы не повредить реальные данные.

## Секреты

Пароли VPS/БД и приватный VAPID-ключ, которые когда-либо отправлялись в переписке или терминале, следует считать раскрытыми и заменить. После замены хранить их только в менеджере паролей, Supabase Secrets или Vault.
