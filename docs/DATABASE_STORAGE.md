# Проверка размера базы — 22 ноября 2026

Измерено через Supabase CLI в связанной рабочей базе, без чтения
содержимого пользовательских записей и без вывода ключей.

До обслуживания размер базы составлял 148 МБ. Основной объём:

| Источник | Размер до обслуживания |
| --- | ---: |
| История pg_cron `cron.job_run_details` | 115 МБ |
| Служебные HTTP-ответы `net._http_response` | 13 МБ |
| Системный каталог Postgres | 12 МБ |
| Все прикладные таблицы `public`, включая индексы | около 4,1 МБ |
| Схема авторизации `auth` | около 4,1 МБ |

В истории pg_cron было около 75 тысяч завершённых успешных запусков,
в том числе около 64,5 тысяч старше недели. Скрипт
`supabase-sql/080_cron_history_retention.sql` удалил устаревшие
технические записи и настроил ежедневную уборку в 04:40 Москвы.
Успешные запуски хранятся 7 дней, неудачные — 30; выполняющиеся
задания не затрагиваются. Сам список cron-задач сохранён.

HTTP-ответов было всего 30 за последние шесть часов: 13 МБ занимали
в основном уже освобождённые, но не возвращённые файловой системе
страницы. Ответы не удалялись вручную: их сроком жизни управляет
pg_net. Выполнено разовое сжатие двух технических таблиц командой
VACUUM FULL с ANALYZE. Эти команды не запускаются ежедневным cron.

После обслуживания база занимает 23 МБ — 4,57% от принятого в
приложении лимита 500 МиБ. История cron — около 2,2 МБ, HTTP-ответы —
64 КБ. Значения со временем изменяются.

Табели, чек-листы, профили, бюджет, уведомления, история отпусков,
журналы действий и входов пользователей не удалялись.
