## О проекте

ALVISA SALARY вырос из калькулятора заработной платы в прикладную систему для сотрудников и руководителей. Приложение объединяет личные и общие табели, графики смен, расчёт выплат, рабочие чек-листы, уведомления и инструменты контроля в одном интерфейсе.

Проект учитывает реальные особенности сменной работы: дневные и ночные часы, переходящие через полночь смены, отпуска и больничные, праздничные и сокращённые дни, региональный производственный календарь, разные нормы рабочего времени и изменения графика в течение месяца.

> Расчёты в приложении являются предварительной оценкой. Официальными источниками итоговых сумм остаются расчётный лист и данные работодателя.

## Возможности

### Табель и рабочее время

- личный табель в классическом, календарном и ленточном представлениях;
- общий табель отдела с разграничением прав доступа;
- дневные и ночные часы, коды отсутствия, праздники и сокращённые дни;
- нормы месяца и первой половины месяца, включая региональные особенности;
- журнал изменений общего табеля для владельца;
- шаблонное составление смен и инструменты выравнивания часов до нормы;
- экспорт личного графика в календарь устройства.

### Выплаты и аналитика

- расчёт зарплаты, аванса и остатка;
- учёт премии, ночных, праздничных часов и переработки;
- оценка отпускных по подтверждённой истории выплат;
- распознавание данных из расчётных листов;
- сравнение расчётных и фактических выплат;
- годовая история и аналитика отклонений.

### Работа смены

- просмотр работающих сегодня и ближайшей смены;
- персональный чек-лист с историей выполненной работы;
- напоминания о сменах, чек-листах и операциях отдела ЕГАИС;
- передача смены следующему сотруднику;
- объявления и push-уведомления на поддерживаемых устройствах.

### Управление

- управление пользователями, отделами и ролями;
- отдельные права редактора, руководителя отдела и владельца;
- ограничения ночных смен для отдельных сотрудников;
- предложения пользователей и уведомления о рассмотрении;
- центр состояния базы данных и критических ошибок интерфейса;
- учебный табель для безопасной проверки инструментов графика.

## Роли

| Роль | Назначение |
| --- | --- |
| Сотрудник | Ведёт личный табель, смотрит смены и выплаты, использует чек-лист и настройки. |
| Редактор отдела | Работает с общим табелем назначенного отдела. |
| Руководитель отдела | Получает доступ к табелю отдела и учитывается специальными правилами составления графика. |
| Владелец | Управляет пользователями и ролями, просматривает аналитику, аудит и состояние системы. |

Права проверяются не только интерфейсом, но и политиками Row Level Security и серверными функциями Supabase.

## Архитектура

| Уровень | Технологии | Ответственность |
| --- | --- | --- |
| Интерфейс | HTML, JavaScript ES Modules, Tailwind CSS | Страницы приложения, формы, табели и клиентские расчёты. |
| Данные и доступ | Supabase Auth, PostgreSQL, RLS, RPC | Авторизация, хранение данных и проверка полномочий. |
| Фоновые задачи | Supabase Edge Functions, `pg_cron`, Web Push | Напоминания, уведомления и служебные операции. |
| Веб-приложение | Service Worker, Web App Manifest | Установка PWA, кеширование оболочки и ограниченная работа без сети. |
| Android | Capacitor | Нативная оболочка для общей веб-кодовой базы. |
| Доставка | GitHub Pages, GitHub Actions | Публикация сайта, проверки качества и сборка тестового APK. |

Клиентское приложение не содержит сервисных ключей Supabase и секретов фоновых задач. Публичный `anon`-ключ работает только вместе с настроенными политиками доступа.

## Локальный запуск

### Требования

- Node.js 22 или новее;
- npm;
- любой локальный HTTP-сервер;
- проект Supabase с применёнными миграциями для полноценной работы с данными.

### Установка и проверка

```powershell
git clone https://github.com/H4nsk0y/Salary.git
cd Salary
npm ci
npm run check
```

`npm run check` пересобирает Tailwind CSS и запускает регрессионные тесты. Та же проверка выполняется GitHub Actions при каждом push в `main` и в pull request.

Приложение состоит из статических файлов, но ES-модули и Service Worker требуют запуска через HTTP. Например:

```powershell
python -m http.server 8080
```

После этого приложение доступно по адресу `http://localhost:8080`.

## Supabase

SQL-изменения хранятся в каталоге [`supabase-sql`](supabase-sql) и применяются последовательно по номеру. Подробный порядок развёртывания, проверки и отката описан в [`docs/SUPABASE_SQL.md`](docs/SUPABASE_SQL.md).

Edge Functions находятся в [`supabase/functions`](supabase/functions). Их секреты задаются в окружении Supabase и не должны попадать в репозиторий.

## Android

Для синхронизации веб-приложения с Android-проектом:

```powershell
npm run cap:sync
npm run cap:open:android
```

Тестовый APK также собирается вручную через workflow **Android debug APK**. Требования, ограничения и порядок сборки описаны в [`docs/mobile-app.md`](docs/mobile-app.md).

## Надёжность и безопасность

- критические операции защищены RLS и серверными RPC-функциями;
- изменения общего табеля записываются в журнал аудита;
- серьёзные ошибки интерфейса собираются отдельно от сетевых сбоев;
- размер базы отслеживается в центре состояния;
- Content Security Policy ограничивает источники исполняемого содержимого;
- автоматические тесты проверяют расчёты, графики, права и основные пользовательские сценарии.

Материалы аудита доступны в [`docs/SECURITY_AUDIT.md`](docs/SECURITY_AUDIT.md) и [`docs/ACCESSIBILITY_AUDIT.md`](docs/ACCESSIBILITY_AUDIT.md).

## Статус

Проект активно развивается и используется как рабочий инструмент. Изменения сначала проходят автоматические проверки, а функции, влияющие на табели и выплаты, дополнительно проверяются на учебных и фактических сценариях.
